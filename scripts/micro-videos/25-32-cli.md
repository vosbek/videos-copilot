## MICRO-25: Shift+Tab Mode Switching

> **Length**: ~60s | **Category**: CLI | **Branch**: N/A

### Script (~80 words)

> One key to rule them all. In Copilot CLI, press Shift+Tab to cycle through execution modes.
>
> Plan mode: Copilot thinks before it acts. It builds a structured plan and asks clarifying questions.
>
> Execute mode: step-by-step with your approval at each stage.
>
> Autopilot mode: full autonomous execution until the task is done.
>
> Watch the mode indicator change in the prompt area. You can switch mid-session - start in Plan, shift to Autopilot once you trust the approach. Full video: F1.

## MICRO-26: /fleet in Action

> **Length**: ~60s | **Category**: CLI | **Branch**: `micro/fleet`

### Script (~100 words)

> Parallelize your work from one command. Type `/fleet` and describe a multi-part task.
>
> "Add a publishers feature: model, routes, tests, frontend component."
>
> The orchestrator decomposes it into independent work items. Model and routes run in parallel. Frontend waits for the API. Tests run alongside routes.
>
> Use `/tasks` to see all agents running simultaneously. Updates stream from different tracks.
>
> The key to good fleet prompts: map deliverables to concrete artifacts. "Create publisher model file, create publisher routes file" is better than "add publishers." Full video: F2.

## MICRO-28: /context Deep Dive

> **Length**: ~60s | **Category**: CLI | **Branch**: N/A

### Script (~100 words)

> Where are your tokens going? `/context` tells you.
>
> Type it mid-session and you get a detailed breakdown. System prompt: X tokens. Loaded customizations: Y tokens. Conversation history: Z tokens. Tool results: W tokens.
>
> This is how you optimize. If a single file read consumed 20% of your context, use more targeted reads next time. If skills are heavy, trim their instruction bodies.
>
> The total bar shows how close you are to the limit. At 95%, auto-compression kicks in - but it's better to manage proactively.
>
> Check `/context` regularly during long sessions. Full video: F5.

## MICRO-29: /resume a Session

> **Length**: ~60s | **Category**: CLI | **Branch**: N/A

### Script (~80 words)

> Pick up where you left off. Type `/resume` to see your recent sessions.
>
> Each entry shows the session date, what you were working on, and a context preview. Select one and your full conversation context restores.
>
> No re-explaining. No starting over. Just continuing.
>
> You can also resume from the command line: `copilot --resume` shows the session picker on startup.
>
> Pro tip: `/resume` also shows cloud agent sessions so you can switch between local and remote work. Full video: F5.

## MICRO-30: & Cloud Delegation

> **Length**: ~60s | **Category**: CLI | **Branch**: N/A

### Script (~90 words)

> Send a long task to the cloud and keep your terminal.
>
> Prefix any prompt with `&`: "& Refactor the entire test suite to use fixtures." The task starts running on the Copilot cloud agent immediately. Your local terminal is free for other work.
>
> The cloud agent runs in an isolated environment with its own compute. Perfect for big refactors, large-scale test generation, or documentation sweeps.
>
> Check on it later with `/resume` - cloud sessions appear alongside local ones. Pick up, review, merge. Full video: F5.

## MICRO-32: CLI Hooks in 60 Seconds

> **Length**: ~60s | **Category**: CLI | **Branch**: `micro/cli-hooks`

### Script (~90 words)

> Hooks work in CLI the same as VS Code. Define them in `.github/hooks/hooks.json`.
>
> Four lifecycle events: `preToolUse` fires before a tool call - block or modify it. `postToolUse` fires after - validate or transform. `userPromptSubmitted` fires before your prompt is processed. `errorOccurred` fires on any error.
>
> Example: a `preToolUse` hook that logs every tool call to a file. A `postToolUse` hook that runs the linter. A `userPromptSubmitted` hook that injects team context.
>
> Same hooks.json, same scripts, every Copilot surface. Full video: F3.
